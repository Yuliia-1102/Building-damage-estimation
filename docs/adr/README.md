# Архітектурні рішення (ADR)

Кожен запис фіксує одне значуще рішення: контекст, розглянуті варіанти, рішення, наслідки та умову, за якої
його треба переглянути. Записи не переписуються: якщо рішення змінюється, створюється новий ADR зі статусом
«Замінює ADR-NNN», а старий отримує статус «Замінено ADR-MMM». Перегляд для нової версії дописується в розділ
«Перегляд» самого запису.

| № | Рішення | Статус | Версія |
|---|---|---|---|
| [ADR-001](ADR-001-web-app-and-worker.md) | Вебсистема на FastAPI з окремим фоновим обробником замість Streamlit | Прийнято; переглянуто для v2.0 — чинне | v1.0 |
| [ADR-002](ADR-002-sqlite-storage.md) | Одна база SQLite (WAL), спільна для сервера й обробника | Прийнято; переглянуто для v2.0 — чинне | v1.0 |
| [ADR-003](ADR-003-simulator-engine.md) | Симулятор із записаних кейсів для розробки і CI без Gemini | Прийнято | v1.0 |
| [ADR-004](ADR-004-single-decision.md) | Одне рішення на заявку: умовний UPDATE і таблиця переходів станів | Прийнято | v2.0 |
| [ADR-005](ADR-005-accounts-and-audit.md) | Власні облікові записи, підписана cookie-сесія і журнал дій у базі | Прийнято | v2.0 |
| [ADR-006](ADR-006-migration-on-start.md) | Ідемпотентна міграція в коді під час старту замість Alembic | Прийнято | v2.0 |

Формат дат: ДД.ММ.РРРР. Посилання на задачі — ключі Jira (проєкт SCRUM) або коди задач спринту (A2, B1, C7, D6).
