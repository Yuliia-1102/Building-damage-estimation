# Операторська вебсистема — що зроблено і як запустити

Етап 3: інструмент із Streamlit-сторінки став системою для оператора, що працює з потоком заявок.
Код оцінювання (`core/`, `models/`, `pricedb/`, `config.toml`) **не змінювався** — вебчастина лише викликає його.
Увесь новий код — у теці `web/`, тести — у `tests/web/`.

## Що зроблено (історії B1–B6)

- **B1** — пакет `web/`, база SQLite (`data/web.db`) з таблицями `application`, `application_file`, `project`, `status_change`.
- **B2** — створення заявки (одне фото / кілька фото / відео до 300 МБ), збереження файлів, sha256, **фоновий обробник** через `core.service.get_engine()`, прогрес, статус `Збій` + «Повторити», відновлення застряглих заявок після перезапуску.
- **B3** — **Kanban-дошка** зі статусами `Створено → Обробляється → Оброблено → Затверджено / Відхилено` (+ `Збій`) і фільтрами (категорія, стан, впевненість, проєкт, дата, вартість, пошук, симульовані).
- **B4** — **сторінка заявки**: зведення, види з масками пошкоджень, параметри будівлі з перерахунком (`reevaluate`, без повторної сегментації), роботи й вартість, PDF, затвердження/відхилення з причиною, історія статусів.
- **B5** — **контроль дублікатів** за sha256: попередження з вибором відхилити / об'єднати / продовжити.
- **B6** — **проєкти** (сума вартості) і **статистика** (за статусами, категоріями, станом, час обробки, частка збоїв; симульовані за замовчуванням не враховуються).

Ціни і матеріали редагуються на сторінці **«Ціни і матеріали»** (`/materials`) вебсистеми; та сама база
(`data/materials.db`) і та сама логіка, що й у старій Streamlit-адмінці (`ui/`), яка теж лишилася.

## Підготовка (один раз)

```powershell
# залежності вебчастини
python -m pip install fastapi uvicorn jinja2 python-multipart httpx fpdf2

# набір тестових кейсів для симулятора: розпакувати devpack.zip у корінь репозиторію
Expand-Archive devpack.zip -DestinationPath .     # має з'явитися devpack\index.json
```

## Запуск вебсистеми (розробка, без ваг моделі й без ключів)

Два вікна PowerShell, у кожному спершу `$env:DAMAGE_ENGINE="simulator"`:

```powershell
# вікно 1 — вебсервер
$env:DAMAGE_ENGINE="simulator"
python -m uvicorn web.server:app --reload
# відкрити http://localhost:8000

# вікно 2 — фоновий обробник
$env:DAMAGE_ENGINE="simulator"
python -m web.worker
```

## Запуск на macOS / Linux через uv

Залежності вебчастини вже є в `pyproject.toml`, тому досить `uv sync --extra ml` (модель потрібна лише для `real`).

```bash
# вікно 1 — вебсервер, http://localhost:8000
DAMAGE_ENGINE=real uv run uvicorn web.server:app --reload
# вікно 2 — фоновий обробник
DAMAGE_ENGINE=real uv run python -m web.worker
```

`DAMAGE_ENGINE=real` — справжня модель сегментації; відповіді мовної моделі за замовчуванням беруться з кешу
(`DAMAGE_LLM_MODE=offline`), Gemini не викликається. Для симулятора — `DAMAGE_ENGINE=simulator` в обох вікнах.

## Робочий режим (продукт, лише Gemini)

```bash
scripts/run_production.sh          # http://localhost:8001, Ctrl+C зупиняє сервер і обробник
```

Кожна оцінка — новий платний запит до Gemini: без кешу відповідей, без заглушок, без тестового набору.
Якщо сервіс не відповів, заявка отримує статус «Збій» з кнопкою «Повторити», а не неповний звіт.
Перерахунок після зміни параметрів — теж новий запит. Заявки, файли й кеш масок — у `data_prod/`,
окремо від розробки (`data/`); ціни спільні (`data/materials.db`). Потрібні ключ у `.env` і ваги моделі.
У шапці видно режим: «робочий режим» або «розробка: …». Облік запитів: `output/gemini_usage.csv`.

## Запуск адмінки цін (окремо, за потреби)

```powershell
streamlit run ui/app.py        # http://localhost:8501, сторінка «Ціни і матеріали»
```

Ціни спільні: обробник бере їх із тієї самої `data/materials.db`, що редагує адмінка.

## Тести

```powershell
$env:DAMAGE_ENGINE="simulator"
python -m pytest tests/web -q        # 14 тестів = 12 сценаріїв захисту
```

## Важливо

- **Симулятор** (`DAMAGE_ENGINE=simulator`): для файлів із `devpack` повертає записаний результат; для будь-яких інших — записаний результат-замінник за хешем файлу (позначка «симуляція»). Справжні зображення й оцінка будуть на моделі `DAMAGE_ENGINE=real` — вебкод при цьому не змінюється.
- Жодних запитів до Gemini вебчастина не робить.
- Не комітити `devpack/`, `data/` (вони в `.gitignore`).

Повніша інструкція — `web/README.md`.
